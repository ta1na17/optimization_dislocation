# Сборка итогового Excel из отчётов дислокации

Внутренний веб-сервис по техническому заданию: загрузка набора `.xls` / `.xlsx`, нормализация, распределение по листам и блокам, подсветка дублей, выдача `Итог.xlsx` и списка отброшенных строк без сохранения результатов на диске проекта и без базы данных.

## Как запустить

Проверил работу с Python 3.12; в ТЗ рекомендован 3.11+ — подойдёт и он.

```bash
cd /path/to/Оптимизация_Дисклокации
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate    # минимальная миграция Django, БД для бизнес-логики не используется
python manage.py runserver 127.0.0.1:8000
```

Открыть в браузере: `http://127.0.0.1:8000`

## Стек и отличия от формулировок ТЗ

- **Backend:** я использую **Django 5 + Django REST Framework**, а не FastAPI, как было «рекомендовано» в ТЗ. Синхронная обработка, без очередей и без хранения истории — как требовалось.
- **Эндпоинты:** вместо ровно `POST /build-report` у меня префикс `api/`:  
  - `GET /api/health/` — проверка живости;  
  - `POST /api/preview-owners/` — предпросмотр собственника по файлам (дополнительно к минимуму ТЗ, чтобы удобно соблюсти валидацию и подсказки в UI);  
  - `POST /api/build-report/` — сборка итога.
- **Ответ сборки:** JSON с полями `file_base64`, `file_name` (обычно `Итог.xlsx`), `duplicates_count`, `dropped_rows_count`, `dropped_rows`. Файл на сервере в каталог проекта я не сохраняю — браузер собирает скачивание из base64 (временные данные при приёме multipart по-прежнему обрабатываются как у Django).
- **Сессии/БД:** SQLite и сессии настроены во временные каталоги ОС, не в репозиторий; бизнес-данные отчётов БД не использует.

## Соответствие требованиям ТЗ (кратко)

Я закладывал следующее поведение:

1. **Вход:** несколько Excel, форматы `.xls` (xlrd) и `.xlsx` (openpyxl).
2. **Выход:** один `Итог.xlsx` с листами **ПСК**, **АлОр**, **Индер**; на **ПСК** есть колонка **г/п**, на АлОр/Индер — нет; колонки **Примечание** и **Статус** в шапке есть, ячейки оставляю пустыми.
3. **Базовые станции и блоки:** на лист **ПСК** попадают только строки, где станция назначения **Калкаман**; на **АлОр** — только **Кызылорда**; на **Индер** — только **Макат** (точное совпадение строки после `strip`, без учёта регистра). Иначе строка **не попадает в итог** и уходит в **отброшенные** с причиной в `dropped_rows` (см. `DROP_REASON_NON_BASE_DESTINATION` в `report_builder.py`). Внутри листа: блок 1 — операция = назначение; блок 2 — назначение = база этого листа и операция ≠ назначение; блок 3 — по коду остаётся для краевых случаев на базе (часто пустой). Между блоками — разделитель **X** и повтор шапки, как в ТЗ.
4. **Сортировка:** блок 1 и 3 — по «дням без движения» убывание; блок 2 — по «осталось км» возрастание (пустые в конце за счёт ключа сортировки).
5. **Собственник:** сначала из содержимого строки/таблицы, при необходимости из имени файла; в UI — список канонических имён и подсказка про переименование; **UVZ** в словаре отнесён к **Модум Транс**. Если авто не находит собственника, я требую выбора в столбце «Вручную» перед сборкой (это строже, чем просто «взять из имени», и снижает риск пустого итога).
6. **Тип вагона:** ПВ/КВ из данных; иначе по собственнику из `OWNER_TO_TYPE`; иначе по кубатуре **120–161 → КВ**, **70–90 → ПВ** (как в ТЗ).
7. **Дубли:** по номеру вагона не удаляю, подсвечиваю светло-жёлтым (`#FFF9C4`).
8. **Отброшенные строки:** возвращаю массив с именем файла, листом, номером строки, кратким превью и **reason** на русском; в интерфейсе — раскрывающийся список по кнопке.
9. **Ошибки API:** формулировки на русском, без traceback в ответе клиенту.

## Где реализация расходится с идеалом ТЗ или оставляет запас

- **Названия станций в Excel:** сравнение с базой **строгое** (например `Кызылорда, КЗХ` не считается равным `Кызылорда`). При необходимости можно добавить нормализацию суффиксов в `_sheet_for_destination`.
- **Причины отбрасывания:** помимо «только вагон» и «нет обязательных полей» в `_normalize_rows`, при сборке добавлено отбрасывание при **назначении не на базовую станцию** — эти строки видны в UI в списке отброшенных с текстом причины.
- **Статус файла в списке:** в ТЗ звучит «имя, размер, статус загрузки»; я показываю имя, размер, **автоопределение собственника** и ручной выбор — это ближе к фактической проверке качества данных перед сборкой.
- **Индикатор обработки:** во время запроса отображается текст «Идет обработка…»; отдельного анимированного спиннера я не делал.
- **«Технолоджи»** как искажённое имя в ТЗ помечено как не использовать без подтверждения — в синонимах я его не добавлял.
